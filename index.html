Rules that cost points

These come from the lectures and from the questions you got wrong in the two practice exams.

Compiling

  • Code that does not compile gets 0 points. Compile after every few lines.
  • Checked exceptions (FileNotFoundException, IOException, InterruptedException) must be caught or declared with throws.
  • String uses length() and charAt(i). Arrays use .length. Lists use size() and get(i).
  • split returns a String[], not a List.
  • A static method has no this, so it cannot use instance fields.

Streams and threads

  • A stream does nothing until a terminal operation, and it can be used only once.
  • count() returns long. sum() exists only on IntStream/DoubleStream. max(), findFirst() and average() return an Optional.
  • A method that returns a Stream must not end with toList().
  • Implementing Runnable starts nothing. Thread.ofPlatform().start(r) runs r.run() in a new thread.
  • Thread order is never guaranteed. Shared data needs synchronized. Locking two objects in opposite order can deadlock.

Equality

  • == on objects compares addresses. Use equals, also for Strings.
  • hashCode uses exactly the fields that equals uses. Equal objects must have equal hash codes.
  • Compare arrays with Arrays.equals. If order does not matter, compare as HashSet.
  • instanceof in equals breaks symmetry with subclasses. Use getClass().

Memory and types

  • Objects and arrays live on the heap. Variables hold references. A method can change the object it gets, but not the caller's variable.
  • Autoboxing is Java turning a primitive into its wrapper. An Integer never becomes a Double.
  • Overloading is decided by the compiler (static binding). Overriding is decided at runtime (dynamic binding).
  • A downcast to the wrong type compiles but throws ClassCastException.

Testing

  • A test stops at its first failed assertion. Write assertEquals(expected, actual).
  • assertThrows(X.class, () -> code) passes when the code throws X.
  • Cyclomatic complexity = number of conditions in if/while/for + 1. The course counts if (a || b) as one condition.

Exceptions and IO

  • throws does not stop an exception. Only catch does.
  • Unchecked = extends RuntimeException. You don't have to catch them.
  • int / 0 throws. double / 0 gives Infinity. Integer overflow wraps silently.
  • Scanner.nextDouble() follows the locale. Double.parseDouble always expects a dot.
  • readLine() returns null at the end of a file, read() returns -1.

Functional Java and streams

The idea

There are three programming styles in the lecture. Imperative: a list of statements that tell the computer how to do it, line by line. Object-oriented: objects with state, changed through methods. Functional: the program is made of functions, data does not change and state is avoided. Functional code is declarative: you say what you want, not how.

The same task, "keep the numbers greater than 5", in both styles:

// imperative: you write the loop, the if and the result list yourself
List<Integer> greater = new ArrayList<>();
for (int i = 0; i < input.size(); i++) {
    Integer element = input.get(i);
    if (element > 5) {
        greater.add(element);
    }
}

// declarative: you only say "filter on > 5"
List<Integer> greater = input.stream().filter(x -> x > 5).toList();

Why functional? It is easier to run in parallel, often shorter and more readable, more flexible, and easier to test.

Lambda expressions

A lambda is a small function without a name. It comes from lambda calculus: λx. x + 1.

Lambda calculus Java Means
λx. x + 1 x -> x + 1 one parameter
λx. λy. x + y (x, y) -> x + y two parameters need brackets
() -> 4 no parameters
x -> { int y = x * 2; return y; } several lines need { } and return

x -> x + 1 is roughly the same as public static int increment(int x) { return x + 1; }. Lambdas should be pure: they should not change variables outside themselves, and the same input should always give the same output.

Functional interfaces: where a lambda is stored

A lambda is stored in a variable whose type is a functional interface (an interface with one method). They live in java.util.function. Each one has its own method name to call it.

Interface Takes → gives Call it with Example
Function<T, R> T → R apply Function<Integer, Integer> inc = x -> x + 1; inc.apply(5) gives 6
BiFunction<T, U, R> T, U → R apply BiFunction<Integer, Integer, Integer> add = (x, y) -> x + y; add.apply(3, 4) gives 7
Predicate<T> T → boolean test Predicate<Integer> gt5 = x -> x > 5; gt5.test(6) gives true
Supplier<T> nothing → T get Supplier<Integer> four = () -> 4; four.get() gives 4
Consumer<T> T → nothing accept Consumer<String> p = s -> System.out.println(s);
Comparator<T> T, T → int compare used by sorted(...)
Runnable nothing → nothing run the same interface as in the threads lecture

There are also versions for primitives, such as IntFunction and IntPredicate.

Passing behaviour as a parameter

The lecture makes a filter method more flexible step by step: first a fixed > 5, then a level parameter, and finally the whole condition as a Predicate:

public List<Integer> filter(List<Integer> input, Predicate<Integer> condition) {
    List<Integer> result = new ArrayList<>();
    for (Integer element : input) {
        if (condition.test(element)) {
            result.add(element);
        }
    }
    return result;
}

List<Integer> greater = filter(input, x -> x > 5);
List<Integer> even    = filter(input, x -> x % 2 == 0);

Trap

  • Lazy: without a terminal operation nothing runs at all. list.stream().filter(...) alone does nothing.
  • Once: a stream can be traversed only once. A second terminal operation on the same stream throws IllegalStateException.
  • Stream<Integer> has no sum(). Write .mapToInt(Integer::intValue).sum() or .mapToInt(x -> x).sum().
  • count() is a long, not an int.
  • If the method's return type is Stream<String>, end with the last map(...). Don't add toList().
  • toList() gives an unmodifiable list: calling add on it throws UnsupportedOperationException.
  • No loops are allowed when the assignment says "use streams". Your score is set to 0 otherwise.

The big example from the lecture, line by line

List<String> result = songs                       // a Stream<Song>
        .map(Song::getArtist)                     // Stream<Artist>
        .filter(artist -> artist.getYearOfBirth() > 1960)
        .map(Artist::getName)                     // Stream<String>
        .distinct()                               // no duplicate names
        .sorted(Comparator.reverseOrder())        // Z to A
        .limit(3)                                 // at most 3
        .toList();                                // terminal: List<String>

The slide ends with .collect.toList(), which does not compile. Use .toList() or .collect(Collectors.toList()).

Sorting with a Comparator

people.stream().sorted(Comparator.comparing(Person::age).reversed())  // oldest first

Optional: no more NullPointerException

person.getCar().getColor() crashes with a NullPointerException when a person has no car. An Optional<Car> is a box that either holds a Car or is empty, so you are forced to handle the empty case.

public class Person {
    private Optional<Car> car;
    public Person()        { this.car = Optional.empty(); }   // no car
    public Person(Car car) { this.car = Optional.of(car); }   // has a car
    public Optional<Car> getCar() { return car; }
}

String color = person.getCar()           // Optional<Car>
        .map(c -> c.getColor())          // Optional<String>
        .orElse("none");                 // String: the color, or "none" if empty
Method Does
Optional.of(x) / Optional.empty() / Optional.ofNullable(x) create one (of(null) throws)
map(f) change the value inside, if there is one
orElse(other) the value, or other if empty
isPresent() / isEmpty() check
get() the value, throws NoSuchElementException if empty
ifPresent(consumer) do something only if there is a value

Stream operations that may find nothing return an Optional: findFirst(), max(), min(), average().

Optional<Person> firstA = persons.stream()
        .filter(x -> x.getName().startsWith("A"))
        .findFirst();
String name = firstA.map(Person::getName).orElse("nobody");

A functional solution! (Practice Exam II). Return the names of ReefShelters with at least minVolume and at least minCoralTypes, as a Stream<String>, without loops:

return shelters
        .filter(s -> s instanceof ReefShelter)                 // keep only reef shelters
        .map(s -> (ReefShelter) s)                             // cast so getUniqueCoralTypes() exists
        .filter(r -> r.getVolume() >= minVolume)               // "at least" means >=

Check yourself

1

Which operation in this pipeline makes the stream actually do work?

list.stream().filter(x -> x > 2).map(x -> x * 2).sorted().count();

count() is the only terminal operation. filter, map and sorted are intermediate and lazy: they only describe the work.

2

What is IntStream.range(2, 5).sum()?

range(2, 5) gives 2, 3, 4 because the end is not included. 2 + 3 + 4 = 9. rangeClosed(2, 5) would give 14.

3

What does List.of(5, 3, 5, 1).stream().distinct().sorted().toList() return?

distinct() removes the second 5, then sorted() puts the rest in natural order.

4

What happens here?

Stream<String> s = names.stream();
long n = s.count();
List<String> l = s.toList();

A stream can be traversed only once. count() already consumed it, so the second terminal operation throws IllegalStateException. The compiler cannot see this.

5

Which type can hold the lambda s -> s.length() > 3 where s is a String?

It takes a String and returns a boolean. That is exactly a Predicate<String>.

6

You have Predicate<Integer> p. How do you call it on 7?

Predicate → test, Function → apply, Supplier → get, Consumer → accept.

7

What is the return type of IntStream.of(3, 4).max()?

The stream could be empty, so max() returns an OptionalInt. Use .getAsInt() or .orElse(…) to get the number.

8

Stream<Integer> nums = …; int total = nums.sum(); What happens?

sum() exists only on IntStream, LongStream and DoubleStream. Write nums.mapToInt(x -> x).sum().

9

Which method reference means the same as s -> s.getName() for a stream of Shelter?

ClassName::instanceMethod calls that method on each element.

10

Optional<Car> c = Optional.empty(); What is c.map(Car::getColor).orElse("none")?

11

A method has return type Stream<String>. Which ending is correct?

You must return the stream itself. toList() and collect give a List, which does not match the return type.

12

What is Stream.of("b", "a", "c").sorted(Comparator.reverseOrder()).findFirst().get()?

Reverse order is c, b, a. The first one is "c".

13

What is IntStream.iterate(0, i -> i + 2).limit(3).sum()?

The infinite stream 0, 2, 4, 6, … is cut to 0, 2, 4 by limit(3). The sum is 6. Without limit it would never end.

14

Inside a lambda you write count++ where count is a local variable. What happens?

Lambdas may read local variables only if they never change. Use count() instead of counting yourself.

Threads

Why threads?

You want to do several things at the same time inside one program. Outlook lets you type an email while it checks for new mail and syncs your calendar. A web server serves pages to many browsers at once.

Process vs thread

Process Thread
What it is roughly a running program one line of execution inside a process
Memory its own private memory shares the memory of its process
Talking to others between processes, e.g. through sockets through the shared objects
How many many processes run on a computer a process can have many threads; a thread belongs to exactly one process

Every Java program starts with one thread: the main thread. When you start another one, there is a second "thread of control" running through your objects.

Concurrency vs parallelism

  • Concurrency: doing many things at the same time.
  • Parallelism: splitting one big job over several processors.

Inside one process there are three ways it can happen:

Hardware What happens
1 processor interleaving: each thread gets a bit of time in turn. The order is not fixed and changes per run and per operating system. Concurrency works fine on 1 core.
more than 1 processor different processors run different threads truly in parallel
hyperthreading the parts of the processor that hold the state are duplicated, the execution parts are not. Switching between threads is very efficient. Most modern CPUs have it.

Heisenbugs are bugs that come from wrong expectations about thread scheduling. They appear in one run and disappear in the next, or when you try to look at them.

Should you use threads? They are not necessary and risky, because a lot can go wrong. They are useful for problems that split up easily: serving web pages, converting a folder of WAV files to MP3 with the same algorithm, or accepting user input while a page loads.

Threads in Java, step by step

Step 1. Implement Runnable. It forces you to write one method: void run(). That is what the new thread will do.

public class AsyncClass implements Runnable {
    public void run() {
        System.out.println("Helperthread 1");
        System.out.println("Helperthread 2");
    }
}

Step 2. Start it. Implementing Runnable and writing run() does not start anything. You need:

public static void main(String[] args) {
    AsyncClass myRunnable = new AsyncClass();
    Thread.ofPlatform().start(myRunnable);   // a platform thread runs myRunnable.run()
    Thread.ofVirtual().start(myRunnable);    // or a virtual thread
}

Because Runnable has only one method, it is a functional interface, so a lambda works too: Thread.ofVirtual().start(() -> System.out.println("hi"));

Two kinds of threads (since Java 21)

Platform thread Virtual thread
Link to the operating system directly connected to an OS thread not directly connected
Resources uses relatively more uses relatively less
Scaling scales OK scales very well
Best for long, continuous, resource-heavy tasks short and simple tasks

Trap

You write What happens
Thread.ofPlatform().start(r) a new thread runs r.run()
r.run() no new thread: a normal method call in the current thread
a method called start() inside your Runnable a normal method that nobody calls. The name means nothing.

The thread only knows your object as a Runnable, and Runnable has only run(). It cannot see any other method you added.

Double the threads, double the trouble

The order in which threads run is not guaranteed. The scheduler decides it, and it differs per operating system and per run. Inside one thread the order of your statements stays the same, but the lines of two threads can mix in any way.

Thread.ofPlatform().start(() -> System.out.println("A"));
System.out.println("B");
// possible output: "A B" or "B A". Both are correct.

Race condition: two threads, one variable

The lecture's example: x = 0, and two threads each run this 10 times:

a = x;        // read
a = a + 1;    // add
x = a;        // write back

You would expect 20, but an update can get lost:

StepThread 1Thread 2x
1a = x (a = 0)0
2b = x (b = 0)0
3x = a + 11
4x = b + 11, not 2: one increment is lost

So after both threads finish, x is at most 20, never more, never below 0, and the exact value is not predictable. Usually it is 20, sometimes less. I ran this with 10,000 increments per thread: in 1 out of 200 runs updates were lost. That is why these bugs are so hard to find.

synchronized

Within one object, only one thread at a time can be active in its synchronized methods or blocks. As soon as one thread enters a synchronized method of object O, no other thread can enter any synchronized method of O until the first one leaves. Other objects of the same class are not blocked, and normal (non-synchronized) methods are not blocked either.

public class SynchronizedCounter {
    private int c = 0;

    public synchronized void increment() {   // whole method locked on this object
        c++;
    }

    public void decrement() {
        synchronized (this) {                // only this block is locked
            c--;
        }
    }
}

With synchronized, two threads that each call increment() 100,000 times always end at 200,000.

Deadlock: waiting for all eternity

Thread T1

is inside o1.m1() (synchronized), so it holds o1

calls o2.m3(), also synchronized

waits for o2

⇄

Thread T2

is inside o2.m2() (synchronized), so it holds o2

calls o1.m4(), also synchronized

waits for o1

Each thread holds the lock the other one needs, so both wait forever. To prevent it, let all threads take locks in the same order, and keep synchronized code short.

Asked in the practice exams

RoadRunner implements Runnable has run() (prints 5 lines "…in 5 minutes" to "…in 1 minutes") and its own start() (prints "Beep-beep!"). main does Thread.ofPlatform().start(new RoadRunner());. No InterruptedException, because nobody calls interrupt().

One more thing (Practice Exam II). True: you can make an algorithm concurrent on 1 core and a process can have multiple threads. False: a process and a thread both represent a running program and a thread can be part of multiple processes.

Not in your slides, but useful

  • Thread.sleep(ms) throws InterruptedException, which is checked. Inside run() you must catch it, because run() cannot declare throws.
  • start(...) returns the Thread. t.join() makes the current thread wait until t has finished: Thread t = Thread.ofPlatform().start(r); t.join();
  • The older way to start a thread, still common online: new Thread(r).start();

Check yourself

1

A class implements Runnable and has a run() method. You create an object of it. How many new threads run?

Implementing Runnable only describes the work. Nothing runs in a new thread until you call Thread.ofPlatform().start(r) or Thread.ofVirtual().start(r).

2

Which line starts a new thread that executes r.run()?

r.run() is a normal call in the current thread. r.start() doesn't exist on Runnable (unless you wrote one, and then it is just a normal method).

3

Can a program be concurrent on a processor with only 1 core?

With 1 core the threads take turns (interleaving). They all make progress, just not at the exact same moment.

4

Which kind of thread fits thousands of short, simple tasks best?

Virtual threads use fewer resources and scale very well. Platform threads fit long, resource-heavy work.

5

Two threads each run x++ 1000 times on a shared int x = 0, without synchronized. What is x at the end?

x++ is read, add, write. If both threads read the same value, one update is lost. It can never go above 2000.

6

Object o has two synchronized methods, a() and b(). Thread T1 is inside o.a(). Thread T2 calls o.b(). What happens?

Only one thread can be active in the synchronized methods of one object. A different object of the same class would not block T2.

7

When can a deadlock happen?

Classic case: T1 holds o1 and waits for o2, T2 holds o2 and waits for o1.

8

Inside run() you write Thread.sleep(1000); without try/catch. What happens?

InterruptedException is checked. run() from Runnable cannot declare it, so you must catch it.

9

How many processes can one thread belong to?

A thread always lives inside exactly one process and shares that process's memory.

10

What does hyperthreading duplicate?

Only the state parts are duplicated, not the execution resources. That makes switching between threads cheap.

11

What is a Heisenbug?

It shows up in some runs and not others, because the thread order changes each time.

12

main starts a thread that prints "A", then prints "B" itself. Which outputs are possible?

The order of two threads is not guaranteed, so either line can come first.

var (since Java 10)

var lets Java infer the type of a local variable from the value you give it:

var list = new ArrayList<String>();   // list is ArrayList<String>
var car = person.getCar();            // car is Optional<Car>
Rule Example that fails

String m = switch (card.getCardType()) {

  • Each case gives one value. Note the ; at the end.

  • No default needed when all cases are covered.

What happens when an exception is thrown

Java leaves the current method and goes back through the call stack (the chain of methods that are still running). Each method gets the same choice:

  1. Catch it and deal with it, or
  2. pass it along to the method that called it.

If nobody catches it, Java's default exception handler prints the stack trace and usually ends the program. You can fix the problem in any method on the call stack: where it goes wrong, where you need the result, or where you can correct it.

try / catch / finally

try {
    String inString = inField.getText();
    int i = Integer.parseInt(inString);        // may throw NumberFormatException
    System.out.println("i = " + i);           // skipped if the line above throws
} catch (NumberFormatException e) {
    System.out.println("Not a number!");      // control jumps here
} finally {
    // ALWAYS runs: after normal end, after an exception, even after return.
    // Use it to clean up: close files, network, locks.
}
  • A try can have 0, 1 or more catch blocks and an optional finally.
  • Put specific exceptions before general ones. catch (Exception e) before catch (IOException e) gives a compile error: exception IOException has already been caught.
  • Catch specific exceptions rather than Exception.
  • Useful: e.getMessage(), e.printStackTrace(), e.getCause(), e.toString().

Passing it along with throws

public void setNumber() throws NumberFormatException {
    int i = Integer.parseInt(inField.getText());   // not handled here; the caller must deal with it
}

throws in the signature does not stop the exception. It only says "my caller must handle this".

When you override a method, you may throw the same or fewer checked exceptions, never broader ones: int read() throws IOException can be overridden by int read() or int read() throws IOException, but not by int read() throws Exception.

Equality, hashCode and records

== vs equals

== on objects compares memory addresses: are these the same object? new Point(3, 4) == new Point(3, 4) is false. equals should compare contents. If you don't write equals, your class uses the one from Object:

public boolean equals(Object obj) {
    return (this == obj);     // Object's version: addresses again
}

That also matters for tests: assertEquals(a, b) calls a.equals(b).

The equals / hashCode template

            && Objects.equals(name, that.name)            // objects: null-safe equals

The equals contract

equals must be an equivalence relation on non-null objects:

Property Rule
Reflexive x.equals(x) is true
Symmetric x.equals(y) gives the same as y.equals(x)
Transitive if x.equals(y) and y.equals(z), then x.equals(z)
Consistent calling it again gives the same result (if nothing changed)
Non-null x.equals(null) is false

Why getClass() and not instanceof

class Vehicle { ... if (!(o instanceof Vehicle)) return false; ... }
class Train extends Vehicle { ... if (!(o instanceof Train)) return false; return super.equals(o); }

Vehicle vehicle1 = new Vehicle("ABC");
Train vehicle2 = new Train("ABC");
vehicle1.equals(vehicle2);   // true:  a Train IS a Vehicle
vehicle2.equals(vehicle1);   // false: a Vehicle is NOT a Train  → not symmetric!

With getClass() != o.getClass() both calls give false, so symmetry holds.

hashCode

HashSet, HashMap and Hashtable store objects in "buckets". hashCode() gives an int, a compression function (simplest: hash % numberOfBuckets) turns it into a bucket number, and only that bucket is searched with equals. Both steps take constant time, so lookups are fast.

A good hash code:

  • is the same for two objects that are equal. This is the rule you must never break. Otherwise a HashSet looks in the wrong bucket and can't find an object that is there.
  • is as unique as possible: many equal hash codes put everything in one bucket, which makes the map slow.
  • uses the same fields as equals, combined with a prime: int result = name.hashCode(); result = 31 * result + address.hashCode(); return result;

A record is a special class for immutable data. You write only the fields; Java generates the rest:

Inheritance and polymorphism

"Is a"

A student is a person, a bike is a vehicle. Inheritance lets you (1) model that relationship, (2) reuse code from the parent, and (3) treat different variants the same way.

class Person {
    private String name;
    public Person(String name) { this.name = name; }
    public String getName() { return name; }
}

class Student extends Person {             // Student is a subclass of Person
    private int studentNumber;
    public Student(int number, String name) {
        super(name);                       // call the Person constructor: MUST be the first line
        studentNumber = number;
    }
}

Words for the same thing: B extends A, B is a subclass / child / derived class of A, A is the superclass / parent of B. The relation is transitive, has no cycles, and forms a hierarchy. In UML: an arrow with a hollow triangle from B to A.

Liskov Substitution Principle: wherever an object of type A is expected, an object of a subclass B is also fine. So Person a = new Student(…) and addPerson(new Student(…)) both work.

Constructors

  • super(...) calls the parent constructor and must be the first statement.
  • If you don't write it, Java inserts super(); automatically. That fails to compile if the parent has no constructor without parameters (e.g. only Person(String nm)).
  • Order of construction: (1) the parent constructor, (2) the fields of the subclass are initialised, (3) the rest of the subclass constructor body.
  • super.method(...) calls the parent's version of a method you overrode.

Subclasses do not get access to the parent's private fields: use getters or protected. Packages (package nl.tudelft.x;, import nl.tudelft.x.*;) group related classes and prevent name clashes.

Declared type vs actual type

A variable has a declared (static) type. An object has an actual (dynamic) type. Say SavingsAccount extends Account:

For primitives a cast converts the value ((int) 3.9 is 3). For references a cast only says "interpret as"; the object itself doesn't change.

Class and object

A class is a blueprint: it defines attributes (data) and methods (operations). An object is an instance of a class with its own values.

public class Point {

Java always passes by value

Java copies the argument into the method's stack frame. For a primitive, the value is copied. For an object or array, the reference (address) is copied. So:

static void swap(int x, int y) { int t = x; x = y; y = t; }     // swaps the copies only
int a = 10, b = 12; swap(a, b);                                  // a, b still 10, 12

static void swap(Point p) { double t = p.x; p.x = p.y; p.y = t; } // changes the shared object
Point p = new Point(10, 12); Point.swap(p);                       // p is now (12, 10)

static void swap(int[] row) { row = copy(row); /* swap */ }       // row now points elsewhere
int[] r = {10, 12}; swap(r);                                      // r still 10, 12

A method can change the object it receives, but never which object the caller's variable points to.

Variable lifetime

A variable declared inside a block { } disappears when the block ends. Using it after the block is a compile error (cannot be resolved to a variable).

// copy (a real copy, not just the address)
public static int[] copy(int[] row) {
    int[] result = new int[row.length];
    for (int i = 0; i < row.length; i++) result[i] = row[i];
    return result;
}

// maximum
public static int max(int[] row) {
    int max = Integer.MIN_VALUE;                 // smaller than every int
    for (int i = 0; i < row.length; i++) if (row[i] > max) max = row[i];
    return max;
}

// linear search: index of x, or -1
public static int index(int[] row, int x) {
    int i = 0;
    while (i != row.length && row[i] != x) i++;  // stop when found or at the end
    return (i == row.length) ? -1 : i;
}

// filter: count first, then copy into an array of the right size
public static int[] filter(int[] row, int level) {
    int[] temp = new int[row.length];
    int number = 0;
    for (int i = 0; i < row.length; i++) {
        if (row[i] >= level) { temp[number] = row[i]; number++; }
    }
    int[] result = new int[number];
    for (int i = 0; i < number; i++) result[i] = temp[i];
    return result;
}

Recursion

A method that calls itself, with a base case that stops it:

public static int sum(int i, int[] row) {
    if (i >= row.length) return 0;            // base case
    return row[i] + sum(i + 1, row);          // recursive call
}
// sum(0, someArray)

Every call gets a stack frame. A wrong stopping condition → endless calls → StackOverflowError.

Container classes: the SpiceRack

A class that manages an array plus a counter:

public class SpiceRack {
    private String[] spiceRack;
    private int numberOfSpices;

    public SpiceRack() {
        spiceRack = new String[6];             // NOT: String[] spiceRack = new String[6];
        numberOfSpices = 0;
    }

    public int index(String spice) {
        for (int i = 0; i < numberOfSpices; i++) {
            if (spiceRack[i].equals(spice)) return i;
        }
        return -1;
    }

    public boolean contains(String spice) { return index(spice) != -1; }   // reuse, no duplicate code

    public String add(String spice) {
        if (numberOfSpices >= spiceRack.length) return "The spice rack is full!";
        if (contains(spice)) return "Spice is already in the rack!";
        spiceRack[numberOfSpices] = spice;    // first empty place
        numberOfSpices++;
        return "Spice has been added";
    }

    public String remove(String spice) {
        int location = index(spice);
        if (location == -1) return "That spice isn't in the rack!";
        for (int i = location; i < spiceRack.length - 1; i++) {   // close the gap
            spiceRack[i] = spiceRack[i + 1];
        }
        spiceRack[spiceRack.length - 1] = null;
        numberOfSpices--;
        return "Spice removed";
    }
}

Trap

The most common container bug: String[] spiceRack = new String[6]; inside the constructor creates a new local variable with the same name. The field stays null, and the next method that uses it throws a NullPointerException. Write spiceRack = new String[6]; (or this.spiceRack = …).

Facts about null: it has no type (null.getX() and new Null() don't work), null == null is true, it can be assigned to any reference type, and a field that is never assigned is null.

Removing by setting a cell to null leaves a gap. The next add uses spiceRack[numberOfSpices] and overwrites a real spice. Close the gap by shifting.

Lecture 14 + Code Review

Code quality, cyclomatic complexity and debugging

External quality is what the user sees: no crashes, good performance. Internal quality is what the developer sees: code that is understandable, easy to change and testable.

Six rules of thumb

  1. Lines of code per method: up to 20 is fine, above 20 review it, above 40 split it. If a piece of code needs a comment to explain it, it probably wants to be its own method.
  2. No duplicated code. Copying code copies its bugs, and you forget to fix all the copies ("late propagation"). Put shared code in one method. With inheritance, put shared logic (like the equals of all trains) in the parent and let children call super.equals(other).
  3. Low cyclomatic complexity (below).
  4. Short parameter lists: calculateDistance(Point p1, Point p2) instead of six ints.
  5. Style: follow conventions (indentation, naming), meaningful names, whitespace, Javadoc.
  6. Testing: aim for 80% line coverage.

Cyclomatic complexity (CC)

CC = the number of linearly independent paths through a method = the minimum number of tests to cover every path. Quick calculation from the lecture: count the conditions of if, while, for … and add 1.

if ((x > 0) && (y > 0)) { … }           // condition 1
else if ((x < 0) && (y > 0)) { … }      // condition 2
else if ((x > 0) && (y < 0)) { … }      // condition 3
else { … }
// CC = 3 + 1 = 4
CC Meaning
0–5 perfect
6–10 hard to understand and test; think about refactoring
above 30 extremely complex

Trap

The course counts one condition per if, also when it contains && or || (see the example above: 3 ifs with && → 4). For Person.equals from Practice Exam I there are 5 ifs → CC = 6. The answer is not 7: the || in if (o == null || getClass() != o.getClass()) is not counted separately here. And the +1 is always there: a method without any if still has 1 path.

Code review

Code review (peer review) means one or more people other than the author examine the code. Goals:

  • improve code quality (internal quality),
  • detect defects (external quality),
  • share knowledge with both the reviewers and the author,
  • comply with QA rules (mandatory in e.g. air traffic and safety-critical software).

In a group project: commit locally → push → open a pull request → automatic checks (tests, Checkstyle) → a maintainer reviews → merge if there are no comments. Unit testing, static analysis and code reviews together catch both maintainability and functional defects.

Review checklist (Michaela Greiler): Does it do what it should? Is it easy to understand? Would smaller methods or better names help? Would comments help, or could code replace them? Is it testable, with enough understandable tests? Is it too complex? Is it formatted nicely? Does each method have a single responsibility?

Version control lets you work together, control parallel changes and roll back to older versions. (Google Docs needs a constant connection; Dropbox makes abc (conflict at 10:17).txt files.) Git stores the history as a graph of line-based changes. It was made by Linus Torvalds in 2005 for the Linux kernel.

  • == and != on objects compare addresses: don't use them for Strings. Be careful with == on doubles too (rounding).
  • && and || are lazy: the right side is only evaluated when needed. x != 0 && 10 / x > 1 is safe when x is 0. & and | always evaluate both sides. ^ is XOR, ! is NOT.
  • Bitwise: 0b00001111 & 0b01010101 = 0b00000101.
  • You can only cast between compatible types. boolean can't be cast to anything.

Control flow

for (int row = 0; row < 8; row++) {              // counter, condition to repeat, increment
    for (int col = 0; col < row + 1; col++) {    // triangle: row + 1 stars
        System.out.print('*');                   // print: no new line
    }
    System.out.println();                        // println: new line
}

while (col < 8) { … }                            // may run 0 times
do { … } while (x > 0);                          // runs at least once

The condition to repeat is the opposite of the stopping condition (row < 8 vs row >= 8).

Methods

public static int max(int x, int y) {   // visibility, static, return type, name, parameters
    int res = x;
    if (y > res) res = y;
    return res;                         // return ends the method
}
  • The signature is the name plus the parameter types. Parameter names don't matter.
  • void returns nothing; you can still use return; to stop early.
  • x and y are the formal parameters; in max(a, b), a and b are the actual parameters.
  • Methods remove duplicated code: put the repeated part in a method and call it.
