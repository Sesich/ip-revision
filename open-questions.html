Functional Java

Imperative vs declarative (functional) programming

Could be asked asExplain the difference between imperative and declarative programming. · Why would you use functional programming in Java?

A language can't be optimal for every use; it trades off speed vs ease of use, reliability vs flexibility, simplicity vs power. The lecture names three paradigms:

Paradigm A program is…
Imperative a sequence of statements that change data, step by step
Object-oriented objects with state, changed through their methods
Functional functions; data is immutable and state is avoided

Imperative code tells the computer how: you write the loop, the condition and where to store the result. Declarative code says what you want: filter(> 5) input in Haskell, input.stream().filter(x -> x > 5) in Java. Java is mainly imperative/OO but has functional elements since Java 8 (lambdas, streams).

What graders look for

  • Imperative = describe how, step by step, with changing state
  • Declarative/functional = describe what; functions, immutable data, no state
  • Example of both (loop with if + add vs filter)
  • Benefits: easier to run in parallel, more concise/readable, more flexible, easier to test

БГИмперативно = казваш как (цикъл, if, add). Декларативно/функционално = казваш какво искаш (filter). Функционалният стил е по-лесен за паралелизиране, по-кратък и по-лесен за тестване.

Model answer

185 words

In imperative programming a program is a sequence of statements that tell the computer step by step how to compute a result, changing variables (state) along the way. For example, to keep the numbers greater than 5 you create an empty list, loop over the input, check each element with an if-statement and add it to the result.

In declarative programming, of which functional programming is a form, you describe what you want instead of how to get it. A functional program consists of functions; data is immutable and state is avoided. In Java the same example becomes input.stream().filter(x -> x > 5).toList(): you only state the condition, and the library takes care of the loop and the result list.

Functional programming is useful because pure functions without side effects are easier to run in parallel, the code is often shorter and more readable, behaviour can be passed around as a parameter (more flexible), and functions that always give the same output for the same input are easier to test. Java is not purely functional, but since Java 8 it supports this style with lambdas and streams.

Avoid: Don't claim Java is a functional language; it is OO with functional elements.

Lambda expressions, functional interfaces, method references

Could be asked asWhat is a lambda expression and how do you use one in Java? · Explain what a functional interface is. · What is a method reference?

A lambda is an anonymous function, from lambda calculus: λx. x + 1 becomes x -> x + 1, λx.λy. x + y becomes (x, y) -> x + y. Java needs a type to store it in: a functional interface, an interface with exactly one abstract method. The lambda becomes the implementation of that method.

Function<Integer, Integer> increment = x -> x + 1;      increment.apply(5);   // 6
BiFunction<Integer, Integer, Integer> add = (x, y) -> x + y;  add.apply(3, 4); // 7
Predicate<Integer> greaterThan5 = x -> x > 5;           greaterThan5.test(6); // true
Supplier<Integer> four = () -> 4;                       four.get();           // 4
filter(input, x -> x > 5);                // behaviour passed as a parameter
filter(input, MyPredicates::greaterThan5); // method reference to an existing method

Local variables used inside a lambda must be effectively final. Runnable and Comparator are functional interfaces too, so Thread.ofVirtual().start(() -> …) works.

What graders look for

  • A lambda is an anonymous function: parameters -> body
  • It is stored in / passed as a functional interface (one abstract method), e.g. Function, Predicate, Supplier
  • Called through the interface method (apply, test, get)
  • Lets you pass behaviour as a parameter (e.g. a filter condition)
  • Method reference Class::method = short form of a lambda that only calls that method

БГЛамбдата е функция без име. В Java тя винаги има тип — функционален интерфейс с точно един абстрактен метод (Function, Predicate…), и се извиква чрез него (apply, test). Така подаваш поведение като параметър.

Model answer

176 words

A lambda expression is an anonymous function: a short piece of behaviour without a name, written as parameters, an arrow and a body, for example x -> x + 1 or (x, y) -> x + y. It comes from lambda calculus, where the increment function is written as λx. x + 1.

In Java a lambda always has the type of a functional interface: an interface with exactly one abstract method, such as Function<T, R> (method apply), Predicate<T> (test), Supplier<T> (get) or Runnable (run). The lambda is the implementation of that method. For example, Predicate<Integer> greaterThan5 = x -> x > 5; can be called with greaterThan5.test(6), which returns true.

The main use is passing behaviour as a parameter. A method filter(List<Integer> input, Predicate<Integer> condition) can be reused with any condition: filter(input, x -> x > 5) or filter(input, x -> x % 2 == 0). Streams use this everywhere (filter, map, sorted).

When a lambda only calls an existing method, you can use a method reference instead, such as MyPredicates::greaterThan5 or Person::getName. Lambdas should be pure: no side effects, same output for the same input.

Avoid: Don't call a lambda directly like increment(5); you call increment.apply(5).

Streams, laziness, intermediate vs terminal

Could be asked asExplain how a stream pipeline works. · What does it mean that intermediate operations are lazy? · Why can a stream only be used once?

A pipeline has a source (a collection, array, range, file lines, or an infinite generator), zero or more intermediate operations (filter, map, distinct, sorted, limit, skip), each returning a new stream, and one terminal operation (toList, count, sum, findFirst, anyMatch, forEach) that produces a result or side effect and closes the stream.

Intermediate operations are lazy: they only describe the work. Nothing runs until the terminal operation. That is why IntStream.iterate(0, i -> i + 2).limit(3).sum() works on an infinite stream, and why findFirst can stop early. A stream can be traversed once; a second terminal operation throws IllegalStateException. Operations should be pure functions (don't change variables outside the stream).

What graders look for

  • Source → 0+ intermediate operations → 1 terminal operation
  • Intermediate operations return a stream and are lazy; only the terminal operation executes the pipeline
  • Laziness allows infinite streams with limit and early stopping (findFirst, anyMatch)
  • A stream can be traversed only once (IllegalStateException)
  • Use pure functions; declarative alternative to loops

БГМеждинните операции (filter, map…) са „мързеливи“ — само описват работата. Нищо не се изпълнява до терминалната операция (toList, count…). Стриймът се ползва само веднъж.

Model answer

186 words

A stream is a sequence of elements that is processed in a pipeline. The pipeline starts with a source, for example list.stream(), Arrays.stream(array), IntStream.range(0, 4) or the lines of a file. Then come zero or more intermediate operations such as filter, map, distinct, sorted or limit. Each of these returns a new stream. The pipeline ends with exactly one terminal operation, such as toList, count, sum, findFirst or anyMatch, which produces the result.

Intermediate operations are lazy: they only describe what should happen and do not process any element. The work is done only when a terminal operation is called. Without a terminal operation nothing happens at all. Laziness makes it possible to work with infinite streams, such as IntStream.iterate(0, i -> i + 2).limit(3), and lets operations like findFirst stop as soon as they have an answer.

After the terminal operation the stream is consumed: a stream can be traversed only once, and using it again throws an IllegalStateException. The functions passed to a stream should be pure, so they don't change variables outside the stream. This makes stream code declarative and easier to parallelize than loops.

Avoid: Don't say filter or map alone produce a result; without a terminal operation nothing runs.

Optional

Could be asked asWhat problem does Optional solve and how do you use it?

person.getCar().getColor() throws a NullPointerException when there is no car. A null check works but is easy to forget. Optional<Car> is a container that either holds a value or is empty, so the type itself says "this may be missing".

private Optional<Car> car = Optional.empty();      // or Optional.of(car)
String color = person.getCar().map(Car::getColor).orElse("none");

Stream operations that may find nothing return an Optional: findFirst(), max(), min(), average() (OptionalDouble).

What graders look for

  • Container that holds a value or is empty
  • Avoids NullPointerException from forgotten null checks
  • Forces the programmer to handle the empty case
  • Optional.of / empty, map, orElse, isPresent
  • Returned by stream operations like findFirst, max

БГOptional е кутия — или съдържа стойност, или е празна. Така типът показва, че стойността може да липсва, и си принуден да обработиш празния случай (orElse) вместо да получиш NullPointerException.

Model answer

159 words

Optional solves the problem of missing values that lead to a NullPointerException. If a person may have no car, person.getCar().getColor() crashes when getCar() returns null. You could add a null check, but it is easy to forget one.

An Optional<Car> is a container object that either contains a Car or is empty. You create it with Optional.of(car) or Optional.empty(). Because the return type is Optional<Car> instead of Car, the caller can see that the value may be missing and is forced to handle that case. For example, person.getCar().map(c -> c.getColor()).orElse("none") applies getColor only if there is a car, and otherwise returns "none". This is shorter than the version with a null check and cannot be forgotten.

Streams also use it: operations that might not find a result, such as findFirst() or max(), return an Optional because the stream could be empty. Calling get() on an empty Optional throws an exception, so it is better to use orElse or isPresent.

Threads

Processes vs threads

Could be asked asWhat is the difference between a thread and a process? · Why would you use multiple threads?

A process is roughly a running program. A computer runs many processes in parallel; each has its own private memory, and processes communicate through e.g. sockets. A thread is a separate flow of control inside one process. All threads of a process share its memory, so they can work on the same objects. Every Java program starts with the main thread.

Use threads to do several things at once within one program: an email client that checks for new mail while you type, a web server that serves many users at the same time, converting a folder of WAV files, accepting input while a page loads. Threads are not necessary and risky; they fit problems that split up easily.

What graders look for

  • Process ≈ running program with its own private memory
  • Thread = flow of control inside a process; threads share the process's memory
  • A process can have many threads; a thread belongs to one process
  • Use: several things at once in one program (examples)
  • Risks: unpredictable order, synchronization problems

БГПроцесът е програма със собствена памет. Нишката е поток на изпълнение вътре в процеса и споделя паметта му с другите нишки. Затова нишките могат да си пречат и трябва синхронизация.

Model answer

194 words

A process is, roughly, a running program. An operating system runs many processes at the same time, and each process has its own private piece of memory. Processes can only exchange information through explicit mechanisms such as sockets.

A thread is a separate flow of control within a single process. One process can contain several threads, and a thread always belongs to exactly one process. All threads of a process work in the same memory, so they can access the same objects directly. Every Java program starts with one thread, the main thread, and can start more.

Threads are useful when one program needs to do several things at the same time: an email program can check for new messages and synchronise the calendar while the user is typing, and a web server can serve pages to many users simultaneously. They work best for problems that are easy to split, such as processing many files with the same algorithm. The downside is that threads are risky: the order in which they run is not fixed, and because they share memory, they can interfere with each other, which requires synchronization and can lead to deadlocks.

Avoid: Don't say threads have their own private memory, or that a thread can belong to several processes.

Concurrency vs parallelism, scheduling, Heisenbugs

Could be asked asExplain concurrency and parallelism. · Can a program be concurrent on a single core? · Why is the order of thread execution not fixed?

The lecture: concurrency = doing many things at the same time; parallelism = splitting one big job over multiple processors. Within one process there are three ways: 1 processor → interleaving (each thread gets a bit of time in turn); more than 1 processor → threads really run at the same time; hyperthreading → the parts of a core that hold the state are duplicated (not the execution resources), so switching is efficient.

The scheduler of the operating system decides which thread runs when. The order is not guaranteed and differs per run and per OS. Bugs caused by wrong assumptions about that order are Heisenbugs: they appear in one run and not the next.

What graders look for

  • Concurrency: many tasks in progress at the same time
  • Parallelism: one job split over several processors
  • 1 core: interleaving (time slices) — concurrency without parallelism
  • Multiple cores: real parallel execution; hyperthreading duplicates state parts
  • Order decided by the scheduler, not fixed → Heisenbugs

БГConcurrency (едновременност) е възможна и на едно ядро чрез редуване (interleaving). Parallelism (паралелизъм) е реално едновременно изпълнение на няколко ядра. Редът на нишките се решава от scheduler-а и не е гарантиран.

Model answer

202 words

Concurrency means that several tasks are in progress at the same time, for example a program that downloads a file while it reacts to the user. Parallelism means that one large job is split up and executed on several processors at the same moment.

Concurrency is possible on a processor with a single core. The threads then take turns through interleaving: each thread gets a small amount of time, after which another thread may continue. All threads make progress, but at any instant only one is running. With more than one core, different threads can truly run in parallel. Hyperthreading is in between: a core duplicates the parts that hold the state of a thread, but not the execution resources, so it can switch between threads very efficiently.

Which thread runs when is decided by the scheduler of the operating system. The order is therefore not guaranteed: it can differ every time the program runs and between operating systems. Programmers must not rely on a particular order. Bugs that come from wrong expectations about thread scheduling are called Heisenbugs, and they are hard to find because they often do not appear again when you run or debug the program a second time.

Avoid: Don't say concurrency needs multiple cores.

Starting threads: Runnable, start vs run, platform vs virtual

Could be asked asHow do you create and start a thread in Java? · What is the difference between platform and virtual threads?

public class AsyncClass implements Runnable {
    public void run() { /* work for the new thread */ }
}
Thread.ofPlatform().start(new AsyncClass());   // new platform thread runs run()
Thread.ofVirtual().start(() -> doWork());       // Runnable is a functional interface

Only implementing Runnable starts nothing. Calling r.run() yourself runs it in the current thread. A method you call start() inside your Runnable is just a normal method (the RoadRunner question).

Platform thread Virtual thread
directly connected to an OS thread not directly connected
relatively more resources fewer resources
scales OK scales very well
long, resource-intensive tasks short, simple tasks (many of them)

What graders look for

  • Implement Runnable with void run(): the work of the thread
  • Start with Thread.ofPlatform().start(r) / Thread.ofVirtual().start(r); run() directly = no new thread
  • Platform: 1-to-1 with an OS thread, heavier, for long resource-intensive tasks
  • Virtual (Java 21): not tied to an OS thread, cheap, scales to many short tasks

БГСамо implements Runnable не стартира нищо. Нишка стартира Thread.ofPlatform()/ofVirtual().start(r), която вика run(). Platform нишките са свързани с нишка на ОС и са „тежки“; virtual нишките са леки и подходящи за много кратки задачи.

Model answer

169 words

To create a thread you first describe its work by implementing the interface Runnable, which has one method, void run(). Implementing Runnable alone does not start anything. You start a thread with Thread.ofPlatform().start(myRunnable) or Thread.ofVirtual().start(myRunnable); the new thread then executes myRunnable.run(). Calling run() yourself is a normal method call in the current thread, and any other method of the object, even one called start, is never called by the thread. Because Runnable is a functional interface, a lambda can also be passed.

Since Java 21 there are two kinds of threads. A platform thread is directly connected to a thread of the operating system. It uses relatively many resources and scales reasonably, so it is best for long-running, resource-intensive tasks. A virtual thread is not directly tied to an operating-system thread; the Java runtime manages it. It uses far fewer resources and scales very well, so you can create very many of them. Virtual threads are best suited for short and simple tasks, such as handling many small requests.

Avoid: Don't confuse run() (normal call) with start(...) (new thread).

Race conditions and synchronized

Could be asked asWhat can go wrong when two threads use the same data? · Explain the keyword synchronized.

x++ is really three steps: read x, add 1, write back. If two threads read the same value before either writes, one increment is lost. In the lecture's example (two threads, each incrementing a shared x 10 times) the result is at most 20, never more, and not predictable.

public synchronized void increment() { c++; }       // lock on this object
public void decrement() { synchronized (this) { c--; } }   // lock only a block

synchronized uses the object's lock: as soon as one thread enters a synchronized method of object O, no other thread can enter any synchronized method of O until it leaves. Other objects are not blocked.

What graders look for

  • Threads share memory → can read/write the same data at the same time
  • Read-modify-write (x++) can lose updates; result unpredictable
  • synchronized method or block: only one thread at a time per object
  • Other threads wait; non-synchronized code is not protected
  • Cost: waiting, risk of deadlock

БГRace condition: две нишки четат една и съща стойност и едното увеличение се губи. synchronized позволява само една нишка наведнъж в synchronized методите на даден обект.

Model answer

199 words

Because threads of one process share memory, two threads can access the same data at the same time. This causes a race condition when the result depends on the timing of the threads. For example, x = x + 1 consists of reading x, adding one and writing the result back. If two threads both read the value 0 before either of them writes, both write 1 and one increment is lost. If two threads each increase a shared counter ten times, the result is at most 20, but it can be lower and differ per run.

The keyword synchronized prevents this. A method declared as public synchronized void increment(), or a block synchronized (this) { ... }, can only be executed by one thread at a time for a given object. As soon as one thread is inside a synchronized method of an object, every other thread that wants to enter any synchronized method of that same object has to wait until the first one leaves. The read-modify-write then happens as one step, so no updates are lost. Objects other than the locked one are not blocked. The price is that threads must wait, and careless use of locks can lead to deadlock.

Avoid: Don't say synchronized locks the whole class or all objects (for instance methods it locks this).

Deadlock

Could be asked asWhat is a deadlock and how can it occur? · How can you prevent a deadlock?

T1 is in synchronized o1.m1() and calls synchronized o2.m3(); T2 is in synchronized o2.m2() and calls synchronized o1.m4(). Each holds the lock the other needs → both wait forever. In Practice Exam I, firstStep locked s1 then needed s2, and secondStep locked s2 then needed s1: "Deadlock can occur."

What graders look for

  • Two (or more) threads each hold a lock and wait for a lock held by the other
  • Caused by synchronized methods calling synchronized methods of other objects
  • Result: threads wait forever, program hangs
  • Prevent: acquire locks in the same order, keep synchronized parts small, avoid nested locking

БГDeadlock: всяка нишка държи ключалка, която другата чака — и двете чакат вечно. Избягва се, като всички нишки заключват обектите в един и същ ред.

Model answer

184 words

A deadlock is a situation in which two or more threads wait for each other forever, so none of them can continue. It can occur with synchronized. Suppose thread T1 is executing the synchronized method m1 of object o1, so it holds the lock of o1. Inside m1 it calls o2.m3(), which is also synchronized, so T1 needs the lock of o2. At the same time thread T2 is executing the synchronized method m2 of o2, so it holds the lock of o2, and calls the synchronized method o1.m4(), for which it needs the lock of o1. T1 waits for T2 to release o2, and T2 waits for T1 to release o1. Neither ever happens, so the program hangs.

Whether a deadlock actually occurs depends on the timing of the threads, which is why one can only say that it can occur. It can be prevented by letting all threads acquire locks in the same fixed order (for example always o1 before o2), by keeping synchronized sections as small as possible and by not calling synchronized methods of other objects while holding a lock.

Avoid: Don't say a deadlock throws an exception; the program just hangs.

Object-oriented concepts

Static vs dynamic binding

Could be asked asExplain binding in Java. · What is the difference between static and dynamic binding?

Binding = associating a method call with a method definition (which code runs).

Animal a = new Dog();     // declared type Animal, actual type Dog
a.makeSound();            // dynamic: JVM picks Dog.makeSound() at runtime (overriding)
print(5);                 // static: compiler picks print(int) over print(String) (overloading)
Math.max(1, 2);           // static: static method
Static (early) Dynamic (late)
decided by compiler JVM at runtime
based on declared type actual object type
applies to overloaded, static, private, final methods; no inheritance overridden instance methods

What graders look for

  • Binding = linking a method call to a method definition
  • Static binding: at compile time by the compiler, based on the declared type
  • Used for overloading and static/private/final methods (no inheritance needed)
  • Dynamic binding: at runtime by the JVM, based on the actual object
  • Used for overriding → enables polymorphism

БГStatic binding решава компилаторът по декларирания тип (overloading, static методи). Dynamic binding решава JVM по реалния обект (overriding) — това прави полиморфизма възможен.

Model answer

180 words

Binding is the process in which a method call is associated with the method definition that will be executed. Java supports two kinds of binding.

Static binding is decided by the compiler, at compile time, based on the declared type of the variable and the types of the arguments. It is used when there is only one possible implementation: for static, private and final methods, and to choose between overloaded methods, which have the same name but different parameter types. For example, the compiler decides that print(5) calls print(int) and not print(String).

Dynamic binding is decided by the Java Virtual Machine at runtime, based on the actual type of the object. It is used for overridden instance methods. If Animal a = new Dog(); and Dog overrides makeSound(), then a.makeSound() executes the version of Dog, even though the declared type is Animal. The compiler only checks that Animal has such a method.

Dynamic binding is what makes polymorphism possible: objects of different subclasses, for example in an Animal[], can be handled in the same way while each executes its own implementation.

Avoid: Don't say overloaded or static methods use dynamic binding (that exact claim was false in Practice Exam II).

Inheritance and the Liskov Substitution Principle

Could be asked asWhy would you use inheritance? · Explain the Liskov Substitution Principle.

class Student extends Person: a Student is a Person. The relation is transitive, has no cycles and forms a hierarchy. The subclass gets all properties of the superclass and can call its public methods; it calls the parent constructor with super(...) as the first statement.

Liskov Substitution Principle: if A is a superclass of B, then wherever an object of type A is required, an object of type B is also acceptable: Person a = new Student(...), addPerson(new Student(...)).

What graders look for

  • "Is a" relationship; subclass extends superclass
  • Reuse: subclass inherits attributes and methods
  • Specialisation / generalisation; model relationships between concepts
  • Polymorphism: treat variants the same way
  • LSP: subclass object usable everywhere the superclass is expected

БГНаследяване = „е“ (Student е Person): преизползваш код и третираш варианти по еднакъв начин. Принципът на Лисков: навсякъде, където се очаква обект от родителя, трябва да може да се подаде и обект от подкласа.

Model answer

193 words

Inheritance is a relationship between two classes in which one class, the subclass, is a special kind of the other, the superclass: a Student is a Person. In Java it is written as class Student extends Person. The relationship is transitive and cannot contain cycles, so classes form a hierarchy.

There are three reasons to use it. First, it models relationships between concepts: the subclass is a specialisation and the superclass a generalisation. Second, it enables reuse: a Student inherits the name, address and methods such as getName() from Person, so they are not implemented twice. Third, it allows different variants to be used in the same way through polymorphism, for example a Cat and a Dog in one Animal[], each with its own makeSomeNoise().

The Liskov Substitution Principle states that if A is a superclass of B, then at every place in the program where an object of type A is expected, an object of type B must also be acceptable. So Person p = new Student(...) is allowed, and a method addPerson(Person p) also accepts a Student. A subclass should therefore never break the behaviour that users of the superclass rely on.

With instanceof: vehicle.equals(train) is true (a Train is a Vehicle) but train.equals(vehicle) is false.

  • getClass() only accepts the exact same class → symmetric
  • Parameter must be Object (override, not overload)

БГequals трябва да е рефлексивен, симетричен, транзитивен и консистентен. instanceof при наследяване може да наруши симетрията — затова ползваме getClass().

Model answer

159 words

The method equals must implement an equivalence relation on non-null objects. It must be reflexive (x.equals(x) is true), symmetric (x.equals(y) gives the same result as y.equals(x)), transitive (if x.equals(y) and y.equals(z), then x.equals(z)) and consistent (repeated calls give the same result as long as the objects don't change). In addition, x.equals(null) must return false. If a class does not override equals, the version of Object is used, which only compares memory addresses.

With inheritance, using instanceof in equals can break symmetry. If Vehicle.equals checks o instanceof Vehicle and Train.equals checks o instanceof Train, then vehicle.equals(train) is true, because a train is a vehicle, but train.equals(vehicle) is false, because a vehicle is not a train. By checking o == null || getClass() != o.getClass(), an object is only equal to objects of exactly the same class, so both calls return false and the relation stays symmetric. The parameter of equals must be of type Object; otherwise the method overloads instead of overrides equals.

200 words

Classes such as HashSet, HashMap and Hashtable use hash codes to store and find objects quickly. When an object is added, its hashCode() is calculated and a compression function, for example the hash code modulo the number of buckets, turns it into a bucket index. To find an object later, only that one bucket is searched with equals, instead of the whole collection. Both steps take constant time.

All throwable problems in Java inherit from Throwable, which has two branches. Errors, such as OutOfMemoryError and StackOverflowError, represent serious system problems that a program cannot reasonably recover from; they should not be caught. Exceptions represent problems that the programmer can and should handle.

Exceptions are either checked or unchecked. Checked exceptions are subclasses of Exception that do not extend RuntimeException, for example IOException and FileNotFoundException. They represent recoverable situations outside the programmer's control, such as a missing file. The compiler forces you to either catch them or declare them with throws, otherwise the program does not compile. Unchecked exceptions extend RuntimeException, for example NullPointerException and ArithmeticException. They usually indicate programming errors, and the compiler does not require you to catch or declare them.

When an exception is thrown, it travels up the call stack until a method catches it with a try/catch block. Only catching stops it; declaring it with throws only passes the responsibility to the caller. If no method catches it, the default exception handler prints the stack trace and terminates the program.

Could be asked asWhat is the difference between Readers/Writers and InputStreams/OutputStreams? · Why use a BufferedReader? · Scanner or BufferedReader?

Data Classes
characters (text files) Reader / Writer
bytes (images, objects) InputStream / OutputStream

A disk access costs ~5 ms = 15,000,000 cycles at 3 GHz. BufferedReader reads big chunks. It is a decorator: it is a Reader and has a Reader. readLine() returns null at the end. Close it (finally or try-with-resources) so the file isn't kept locked. java.io is stream-oriented and blocking; java.nio is block-oriented with buffers and non-blocking.

What graders look for

  • Reader/Writer: characters (text); InputStream/OutputStream: raw bytes; InputStreamReader converts
  • Reading one char at a time from disk is slow → buffering reads chunks
  • BufferedReader = decorator (is a Reader, has a Reader), readLine()
  • Scanner: slower but convenient (nextInt, delimiters); BufferedReader: faster, efficient
  • Always close (try-with-resources)

БГReader/Writer = символи (текст), InputStream/OutputStream = байтове. BufferedReader чете на големи парчета, защото дискът е бавен. Scanner е по-удобен, BufferedReader — по-бърз.

Model answer

187 words

The java.io library has two families of classes. Readers and Writers are designed for character streams and are used for text files. InputStreams and OutputStreams work with raw bytes without translating them, and are used for binary data such as images or serialized objects. An InputStreamReader can turn a byte stream into a character stream.

Reading a file character by character, for example with FileReader.read(), is slow, because every access to the disk takes milliseconds, which is millions of processor cycles. A BufferedReader solves this by reading a large block of characters at once into a buffer and serving the following reads from memory. It is an example of the decorator pattern: a BufferedReader is a Reader and also has a Reader, adding buffering and a convenient readLine() method to any reader.

A Scanner is more user-friendly and flexible: it can split input into tokens with a delimiter and read numbers directly with methods like nextInt(). A BufferedReader is faster and more efficient but only reads characters and lines. In both cases the file must be closed afterwards, preferably with try-with-resources, so it is not kept locked.

Saving objects: DataOutputStream vs Serializable

Could be asked asHow can you write an object to a file? · What does the Serializable interface do?

// manual
public void save(DataOutput out) throws IOException { out.writeUTF(name); out.writeDouble(rate); }
// automatic
class CurrencyTable implements Serializable { … }
out.writeObject(table);   CurrencyTable t = (CurrencyTable) in.readObject();

What graders look for

  • DataOutputStream: write primitives/Strings yourself (writeUTF, writeDouble), read back in the same order; full control, but the class handles its own storage
  • Serializable: marker interface, no methods; ObjectOutputStream.writeObject stores the whole object
  • readObject returns Object → cast; ClassNotFoundException
  • Non-serializable class → NotSerializableException

БГDataOutputStream: сам записваш полетата и ги четеш в същия ред. Serializable е маркер интерфейс без методи — ObjectOutputStream записва целия обект с writeObject.

Model answer

174 words

There are two ways to store objects. With a DataOutputStream you decide yourself how an object is saved: the class gets a method such as save(DataOutput out) that writes each attribute with writeUTF, writeDouble, and so on, and a matching load method that reads them back with readUTF and readDouble in exactly the same order. This gives full control over the format, but the class itself becomes responsible for storage, and every change to its attributes requires changing both methods.

Alternatively, a class can implement the interface Serializable. It is a marker interface: it has no methods to implement, it only indicates that objects of the class may be serialized. An ObjectOutputStream can then write a complete object, including the objects it refers to, with writeObject(obj), and an ObjectInputStream reads it back with readObject(). Because readObject returns an Object, the result must be cast, and it can throw a ClassNotFoundException. If an object, or one of its attributes, does not implement Serializable, a NotSerializableException is thrown. A DataOutputStream cannot write arbitrary objects at all.

Avoid: Don't say Serializable requires you to implement methods.

Testing, quality and tools

Unit testing principles

Could be asked asWhy should you write unit tests? · What makes a good test? · Unit tests vs integration tests?

"Compiling software ≠ working software." JUnit: @Test public void …(), assertEquals(expected, actual), assertThrows(X.class, () -> …). Positive (good weather) vs negative (bad weather) tests: assertEquals(5, max(5, 3)) vs assertNotEquals(4, max(5, 3)).

What graders look for

  • Find bugs early (cheaper); compiling ≠ working; automated and repeatable
  • Unit test = one method/class in isolation; integration test = classes working together
  • Good and bad weather tests
  • One workflow per test, few asserts → failure location is clear
  • Can't test everything: "presence, not absence of bugs"; aim for coverage (80%)

БГUnit тестът проверява един метод/клас изолирано; integration тестът — как класовете работят заедно. Тествай и „добро“, и „лошо време“; един сценарий на тест.

Model answer

203 words

Code that compiles is not necessarily correct. Unit tests check automatically whether a piece of code behaves as expected, and they can be repeated after every change. Testing early is cheaper, because bugs found later cost more to fix.

A unit test checks one method or class in isolation, for example that setLength(10) really changes the length of a rectangle. An integration test checks whether several classes work together correctly, such as a Person that stores an Address. When an integration test fails, the mistake could be in any of the methods it uses, so each class should also have its own unit tests.

A good test has a clear purpose: one workflow per test method and few assertions, so that the name of a failing test already tells you what went wrong. You should test both positive scenarios (good weather), where the correct result is expected, and negative scenarios (bad weather), where unexpected input is used or a wrong result must not occur. Exceptions are tested with assertThrows. Tests can never prove that code is correct: as Dijkstra said, testing shows the presence, not the absence of bugs. Line coverage, for example 80%, shows how much code is executed by the tests.

Cyclomatic complexity

Could be asked asWhat is cyclomatic complexity and why does it matter? · How many tests do you need for this method?

CC = number of linearly independent paths. Quick rule (lecture): count the conditions of if, while, for, … and add 1. The course counts if (a || b) as one condition (the Person.equals question: 5 ifs → 6).

CC Meaning
0–5 perfect
6–10 hard to understand/test, consider refactoring
> 30 extremely complex

What graders look for

  • Number of linearly independent paths through a method
  • Quick calculation: number of conditions + 1
  • Minimum number of tests to cover every path
  • High CC → hard to understand and test → refactor into smaller methods

БГЦикломатичната сложност = брой независими пътища = минималният брой тестове. Брои се: условия в if/while/for + 1. Курсът брои if (a || b) като едно условие.

Model answer

170 words

Cyclomatic complexity is a measure of how complex a method is: it is the number of linearly independent paths through the code. A quick way to calculate it is to count the conditions of the if-statements, loops and other branches, and add one. A method without any branch has a complexity of 1; a method with an if and two else-ifs has a complexity of 4.

The measure matters for two reasons. A high cyclomatic complexity makes code hard to understand, because the reader must keep many possible paths in mind. It also makes code hard to test, because each path should be covered by at least one test: the cyclomatic complexity is the minimum number of tests needed to execute all linearly independent paths. A value up to about 5 is considered fine, between 6 and 10 the method should be reviewed and possibly refactored, and above 30 it is extremely complex. The usual solution is to split the method into smaller methods that each have a single task.

Code quality and code review

Could be asked asWhat is the difference between internal and external quality? · What are the goals of code review?

Rules of thumb: method ≤ 20 lines (> 40 split), no duplicated code (bugs get copied; "late propagation"), low CC, short parameter lists (group into objects), code conventions + Javadoc, 80% coverage. Tools: static analysis (Checkstyle), project managers. Review flow: commit → pull request → automatic checks → review → merge.

What graders look for

  • External quality: user view (no crashes, performance)
  • Internal quality: developer view (understandable, changeable, testable)
  • Rules: short methods, no duplication, low CC, short parameter lists, style/Javadoc, tests
  • Code review: someone else examines the code
  • Review goals: code quality, find defects, knowledge transfer, comply with QA standards

БГВъншно качество — за потребителя (без сривове, бързина). Вътрешно — за програмиста (четим, лесен за промяна и тестване). Code review: друг човек преглежда кода, за да намери грешки и да споделят знания.

Model answer

189 words

External quality is quality from the user's point of view: the program does not crash, gives correct results and performs well. Internal quality is quality from the developer's point of view: the code is understandable, easy to change and testable. Internal quality also affects external quality, because testable code is tested better.

Simple rules help internal quality: keep methods short (up to about 20 lines), avoid duplicated code, because copied code also copies bugs and changes are easily forgotten in one of the copies, keep the cyclomatic complexity low, group long parameter lists into objects, follow code conventions, use meaningful names and write Javadoc. Static analysis tools such as Checkstyle check many of these rules automatically.

Code review is a quality assurance activity in which one or more people other than the author examine the source code, typically in a pull request before it is merged. Its goals are improving the internal quality of the code, detecting defects, sharing knowledge about the code base and solutions between reviewers and author, and complying with quality guidelines, which is mandatory in safety-critical software. Code review complements unit testing and static analysis.

Version control and Git

What graders look for

  • Work together, control parallel changes, roll back to earlier versions
  • Distributed: local repository + remote repository
  • add → staging, commit → local, push → remote, pull ← remote

Model answer

207 words

Version control lets developers work together on the same code efficiently, keep control over changes that are made in parallel, and roll back to any earlier version. Simple solutions such as file names like report_final_final2.doc or Dropbox do not resolve conflicting changes.

Git is a distributed version control system. Each developer has a working copy of the files and a local repository with the full history, and there is a shared remote repository. With git add a new or changed file is placed in the staging area. With git commit the staged changes are saved as a new version in the local repository. git push sends local commits to the remote repository so collaborators can see them, and git pull brings their changes to your computer. git clone creates a local copy of a remote repository, and git checkout restores the last committed version of a file. Git stores line-based increments, which is very efficient for source code.

The main challenge is merging parallel changes. When two developers change the same lines, Git cannot merge them automatically, even with a three-way merge. It marks the conflict in the file, and a developer has to decide what the meaningful result is, for example keeping both versions, before committing.

Libraries vs frameworks; debugging

Could be asked asWhat is the difference between a library and a framework? · How do you find a bug with the debugger?

Manual coding Library Framework
full control, repetitive work you call it (ArrayList, Scanner) it dictates the possibilities (JUnit)

What graders look for

  • Library: you call its code when you need it; you keep control
  • Framework: defines the structure and calls your code; full workflow support, good if it fits
  • Debugging: print statements vs debugger
  • Breakpoints, step into / over, inspect variables, conditional breakpoints

БГБиблиотеката я викаш ти (ArrayList). Framework-ът определя структурата и вика твоя код (JUnit). Дебъгерът спира на breakpoint и можеш да гледаш променливите стъпка по стъпка.

Model answer

188 words

A library is a collection of ready-made code that your program calls when it needs it, for example ArrayList, Objects or Scanner from the Java standard library. You stay in control of the structure of the program and only avoid reinventing the wheel. A framework provides support for a whole workflow and dictates the structure: it determines the possibilities and calls your code at the right moments. JUnit is an example: you write methods annotated with @Test, and the framework finds and runs them. A framework is very productive when it suits your needs, but gives less control.

A failing test shows that there is a bug, but not where it is. Print statements that show the values of variables during execution help, but a debugger is more powerful: you set a breakpoint on a line, run the program in debug mode, and it pauses there. You can then inspect all variables, step over a line or step into a method call, and continue to the next breakpoint. Conditional breakpoints or hit counts pause only in a specific situation, such as when i == 3, which helps with loops.

var: should you use it?

Could be asked asExplain the keyword var. Should you use it?

var list = new ArrayList<String>(); — the type is inferred at compile time and stays fixed. Only for local variables with an immediate value; var x; and var f = x -> x + 1; don't compile.

What graders look for

  • Type inference for local variables (since Java 10)
  • Still static typing: type fixed at compile time; compile error if it can't be inferred
  • Only local variables, must be initialised
  • Pros: less typing, readable with long generic types, easier refactoring; cons: type not visible
  • Be consistent within a team

БГvar само извежда типа при компилация — Java остава статично типизиран. Само за локални променливи с начална стойност. Плюс: по-малко писане; минус: типът не се вижда.

Model answer

185 words

The keyword var, introduced in Java 10, lets the compiler infer the type of a local variable from the value it is initialised with. Instead of ArrayList<String> list = new ArrayList<String>(); you can write var list = new ArrayList<String>();. The variable still has a static type: it is determined at compile time and cannot change, so var number = 3; number = "hello"; does not compile. If the compiler cannot determine the type, for example var x; without a value or a lambda without a target type, the program does not compile either. var can only be used for local variables that are immediately initialised, not for attributes, parameters or return types.

Whether to use it depends on whom you ask. It saves typing and can make code with long generic types easier to read and to refactor. On the other hand, the type is no longer visible in the code, which can make it harder to understand; in an IDE such as IntelliJ you can hover over the variable to see it. The most important thing is to be consistent and agree on its use within your team.

Avoid: Don't say var makes Java dynamically typed.

Enums and switch expressions

Could be asked asWhy use an enum instead of a String? · What is the difference between a switch statement and a switch expression?

public enum CardType { NORMAL, RARE, EPIC, LEGENDARY; }
String m = switch (card.getCardType()) {
    case NORMAL, RARE, EPIC -> "nothing special.";
    case LEGENDARY -> "a legendary!";
};

What graders look for

  • Enum: fixed set of named constants; type-safe (typos → compile errors), only valid values
  • Can have fields, a (private) constructor and methods; values(), ordinal(), compareTo
  • Switch statement: needs break, falls through, default
  • Switch expression: ->, evaluates to a value, no fall-through/break, no default if all cases covered

БГEnum вместо String: компилаторът приема само валидни стойности. Switch expression (->) връща стойност, няма fall-through и break, а default не е нужен, ако всички случаи са покрити.

Model answer

181 words

An enum defines a type with a fixed set of named constants, for example enum CardType { NORMAL, RARE, EPIC, LEGENDARY }. It is a better alternative to storing such values in a String, because the compiler then only accepts valid values: a typo such as "EPICC" in a String goes unnoticed, while CardType.EPICC does not compile. Enums can also have attributes, a constructor and methods, for example a description for each card type, and their constants have a fixed order, so they can be compared.

A classic switch statement executes different code depending on a value of a primitive type, String or enum. Each case needs a break, otherwise execution falls through into the next case, and a default case handles remaining values. A switch expression, written with arrows (case LEGENDARY -> "a legendary!";), evaluates to a single value that can be assigned directly to a variable. There is no falling through, so no break is needed, and when all possible values are covered, as with all constants of an enum, no default is needed. This makes the code shorter and less error-prone.

Comparable vs Comparator

Could be asked asHow can you sort a list of your own objects? · What is the difference between Comparable and Comparator?

public record Person(String name) implements Comparable<Person> {
    public int compareTo(Person o) { return this.name.compareTo(o.name); }
}
Collections.sort(people);                                   // natural order
people.sort(Comparator.comparing(Person::age).reversed());  // other order

What graders look for

  • Collections.sort needs to know the order; built-in for Integer, String
  • Comparable<T>: implemented by the class itself, compareTo(T o), one natural order
  • compareTo: negative = this first, 0 = equal, positive = this after
  • Comparator<T>: separate object/lambda, compare(a, b); many orders without changing the class

БГComparable: класът сам определя естествения си ред чрез compareTo (отрицателно = преди, 0 = равни, положително = след). Comparator: отделно правило отвън — може да имаш много подредби.

Model answer

162 words

Collections.sort can sort lists of Integer or String because these classes already define an order. To sort objects of your own class, Java must know how two objects compare.

One way is to let the class implement the interface Comparable<T> and its method compareTo(T o). The method returns a negative number if this should come before o, zero if they are equal in ordering, and a positive number if this should come after o. For example, a Person can compare by name with return this.name.compareTo(o.name);. This defines the natural order of the class, which Collections.sort(people) then uses. A class can only have one natural order.

A Comparator<T> is a separate object, often a lambda, with a method compare(a, b) following the same sign rules. It defines an ordering from outside the class, so you can sort the same objects in different ways without changing the class, for example people.sort(Comparator.comparing(Person::age)) or with .reversed() for the opposite order. Streams use comparators in sorted(...).
